# Scenario Branch Compiler v6 留出验证

## 为什么优化

角色规模实验显示，8 个角色已经全部实际参与并平均产生 23.75 个自主行动，但旧版 v5
情景槽位按行动相关性排序，容易反复选中少数高分角色。4 个开发事件的最终情景平均只覆盖
4.25 / 8 个角色。问题位于情景汇总层，不在角色调度或 OASIS 行动层。

v6 保留行动相关性评分，但每选择一个角色组合时优先覆盖尚未进入其他情景的角色。模型仍然
负责写出触发条件、后果、失效条件和机制说明；角色 ID 与已有金融决策继续由系统确定性绑定。
对 4 个及以上有效决策角色，编译器要求恰好生成 4 条分支。

## 冻结留出设计

- 开发事件：角色消融中的 4 个八角色事件；
- 留出事件：24 个主样本中配置为 8 角色、但未进入角色消融的其余 4 个事件；
- 覆盖：CN/US 各 2 个，并购与宏观事件各 2 个；
- 对照：v5 和 v6 使用完全相同的已密封模拟行动与结构化金融决策；
- 主指标：最终情景覆盖的配置角色比例；
- 不读取 CAR、涨跌或其他市场结果标签。

冻结清单哈希：`8d98ae6c40d48538a616abdb80f7914a61bb9ba24ad75d1c8b407909399f9c04`。

## 结果

| 指标 | v5 | v6 | 变化 |
|---|---:|---:|---:|
| 配置角色覆盖率 | 43.8% | 96.9% | +53.1 个百分点 |
| 有效决策角色覆盖率 | 45.5% | 100.0% | +54.5 个百分点 |
| 平均情景分支数 | 3.25 | 4.00 | +23.1% |
| 结构完整率 | 100% | 100% | 持平 |
| 不同角色组合数 | 3.25 | 4.00 | +23.1% |

v6 的配置角色覆盖是 v5 的 2.21 倍。4 / 4 个留出案例覆盖了全部具有有效结构化决策的
角色；其中一个案例有 1 / 8 个角色的金融决策生成失败，因此配置角色覆盖率上限为 87.5%，
四例平均为 96.9%。新增编译共 4 次模型调用、23,804 tokens，估算成本 $0.0025，
中位耗时 35.8 秒。

## 复现

冻结或检查清单，不调用模型：

```bash
make scenario-coverage-manifest
make scenario-coverage-plan
```

确认模型配置和费用后运行；已密封输出会被复用：

```bash
make scenario-coverage-run ALLOW_BILLABLE=1
```

结果默认写入 `.data/experiments/scenario-coverage-v1/`。扩大实验打包命令会把清单、紧凑结果、
图以及四组脱敏输入/输出一并复制到 FEVER 回测目录。

## 解释边界

这是用户可见产物的工程覆盖指标，适合说明“增加的角色观点确实进入最终情景”。它不衡量
市场涨跌准确率，也不把合成分支当作概率或新证据。角色槽位覆盖由算法保证；留出验证确认的
是端到端模型输出能遵守四分支契约、保持结构完整，并把这些槽位转化成可读情景。
