# MiroFish 金融情景决策支持评测包

本包回答的不是“多智能体能否准确预测股价”，而是更适合当前模块定位的三个问题：固定四条
情景时，系统是否保留了足够多的参与方行动，情景是否可监测、可推翻，以及是否覆盖了后来
发生的事件路径。

## 可以写进报告的结果

- 在 12 组完全相同的封存模拟上，v6 将有效决策角色覆盖率从
  **75.0% 提升到 100.0%**，即
  +25.0 个百分点；该数字由结构化 ID 直接复算，不依赖模型裁判。
- 严格合格情景率从 12.5% 到
  18.8%，但质量均分 10.88→
  10.79，属于混合结果。
- v5 与 v6 的完整事件路径 Recall@4 均为 50.0%；
  含部分命中从 62.5% 到
  66.7%。路径状态双评一致率只有
  58.3%，因此仅作描述性诊断。
- 首轮单智能体 A 与旧 v5 多智能体 B 的完整路径 Recall@4 分别为
  41.7% 与 33.3%；旧 B 没有
  显示优势，而且成对质量评审存在严重位置偏差。负结果被完整保留，没有挑选性删除。

当前最合适的产品主张是：**情景编译器能更完整地保留多方行动并形成可审计的观察清单**。
当前证据不支持“预测更准”或“多智能体文本整体优于单智能体”。

## 文件

- `report-retrospective.*`：单智能体 A 与旧 v5 多智能体 B 的回顾诊断；
- `report-compiler-diagnostic.*`：在相同模拟上隔离比较 v5 与 v6；
- `cases/`：12 个匿名 D0 输入、仅事件类结果、冻结情景和两次独立评审；
- `PROTOCOL-*.md`：调用前冻结的评测规则与事后诊断边界；
- `verify_results.py`：仅用 Python 标准库校验文件哈希、隐私字段并复算主要数字。

## 离线复算

```bash
python3 verify_results.py
```

该命令不联网、不调用模型，也不需要安装 FEVER 依赖。完整重新生成需使用 FEVER-MiroFish
研究工作区的 `decision-support-eval-*` 与 `compiler-diagnostic-*` 命令，并显式允许计费。

## 隐私与解释边界

包内只保留匿名事实、匿名参与方、匿名事件目标及结果；不包含 API Key、真实证券代码、市场
收益、真实来源 URL 或本机路径。两轮均为回顾性方法验证，且低成本模型同时参与生成与评审；
后续正式结论应由新盲样本和独立人工或异构模型评审确认。
