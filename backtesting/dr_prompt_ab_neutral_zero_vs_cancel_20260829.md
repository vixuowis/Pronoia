# Neutral：0:0 与多空抵消分析（最终1000条）

## 方法限制

当前裁决结果没有结构化保存 `up_score/down_score/net_score`，只有自然语言 rationale。本报告用可复核正则识别：

- **明确/清晰0:0**：出现 `up=0/down=0`、`up和down均为0`、`无任何方向信号`等表述；
- **明确抵消**：出现“抵消、同强度平衡、正负信号平衡”等表述；
- **净分0但不透明**：只写 `净分=0`，未展示分项；
- **无评分轨迹**：neutral但理由没有可解析的打分说明。

所以0:0和抵消数字是高置信下限；“净分0但不透明”不能可靠二分。

## 全部 Neutral 的构成

| 类型 | v0（neutral=883） | claim-v2（neutral=869） |
|---|---:|---:|
| 明确/清晰 up=0、down=0 | **594（67.3%）** | **581（66.9%）** |
| 明确多空抵消 | **33（3.7%）** | **24（2.8%）** |
| 只写净分=0，分项不透明 | 236（26.7%） | 242（27.8%） |
| 没有可解析评分轨迹 | 20（2.3%） | 22（2.5%） |

结论：neutral 的主体是“模型认为完全没有可计分方向信号”，不是正负证据相互抵消。明确0:0约为明确抵消的18–24倍。

## False-neutral 中的0:0

False-neutral定义为真实T3标签为up/down，但预测neutral：

| 指标 | v0 | claim-v2 |
|---|---:|---:|
| False-neutral总数 | 711 | 702 |
| 明确/清晰0:0 false-neutral | **480** | **467** |
| 占false-neutral | **67.5%** | **66.5%** |

也就是说，仅明确0:0这一类就吞掉了接近一半的全部1000条样本，是当前ACC低的最大单一机制。

## 0:0 False-neutral 的互斥主因

| 主因 | v0（n=480） | claim-v2（n=467） |
|---|---:|---:|
| 事件输入缺失，同时工具/行情取数失败 | **411（85.6%）** | **411（88.0%）** |
| 仅事件输入或公告正文不完整 | 40（8.3%） | 24（5.1%） |
| 仅工具取数或行情链路失败 | 22（4.6%） | 26（5.6%） |
| 已有专家/工具证据未被图谱完整提取 | 3（0.6%） | 2（0.4%） |
| 程序性事件直接归为无方向 | 2（0.4%） | 4（0.9%） |
| 裁决器未把现有claim映射为方向 | 2（0.4%） | 0 |

这里的“事件输入缺失 + 工具取数失败”通常是组合问题：packet只有标题/模板占位，缺actual、consensus、前值、交易对价或业绩数字；同时event study、T0、pre5/pre20漂移或行情工具超时/失败。于是图谱创建大量missing/needs_more，裁决器将up/down都记为0。

## 重叠诊断信号

在明确0:0 false-neutral中（类别可重叠）：

| 诊断信号 | v0 | claim-v2 |
|---|---:|---:|
| 图谱未闭合/存在missing或needs_more | 480 | 467 |
| 事件packet或公告缺正文/关键数值 | 451 | 435 |
| 工具失败或T0/漂移证据缺失 | 433 | 437 |
| 程序性/低信息量事件 | 236 | 210 |
| 已有专家/工具证据未完整进入claim | 218 | 188 |
| event_type与正文错配 | 25 | 19 |

“已有证据未完整进入claim”的重叠数较高，说明即使某个expert摘要或tool trace里有行情线索，Deep Researcher也常在claim中说“数值未呈现/不可读”，最后仍归零。它通常同时伴随packet和工具问题，所以在互斥主因里没有被列为首因。

财报和宏观意外类本应最依赖actual-vs-consensus。一旦packet只有占位文本且外部取数失败，就必然形成0:0；这是最值得优先修的数据链路。

## 结论与修正优先级

1. **首要问题是证据可用性，不是冲突抵消。** 明确抵消只占约3%，明确0:0占约67%。
2. 优先补齐packet中的actual/consensus/previous、公告正文、交易条款，并让T0/pre-drift以结构化数值直接进入图谱。
3. 工具返回成功时，不应只写“返回1行/工具已执行”；必须把关键数值复制到Evidence节点和signed claim。
4. `needs_more`只能降低confidence，不能自动令方向分数为0；条件方向应保存符号和触发条件。
5. 裁决器必须结构化输出 `up_score/down_score/net_score/decisive_claim_ids`。否则约28%的neutral仍无法审计究竟是0:0还是抵消。
